# Ashare-sector-rotation

**给 AI agent 用的 A 股板块/ETF 分析「纪律层」。** 问一句「这个板块现在能不能买」，
你拿到的是一份可审计的结论：胜率、象限、站得住的仓位、三档价格——以及它**拒绝更乐观**的
全部理由。

它不是预测模型，是一层纪律。

## 它要解决的问题：LLM 会很自然地编数

你问任何一个够强的模型「512800 现在能不能买」，都会得到一段自信、排版齐整的回答。
但你从那堆文字里**拿不到**这些：

- 哪些数字是**取来的**，哪些是**假设的**；
- 其中一个偏了 20%，结论会漂多远；
- 因为某个数据源返回空，信心实际掉了多少；
- 支撑这个结论的框架，和上个月那份结论用的是不是同一个。

「AI + 量化」的常见做法是让模型算数、然后相信它。这个仓库反过来。

## 这个仓库到底是什么

两半，被人为分开，并由代码强制：

| 一半 | 归谁 | 允许碰什么 |
|---|---|---|
| 叙事判断——需求格局、行业周期位置、前瞻、催化 | **LLM / agent** | 只有自由文本字段 |
| 每一个数字——分位、胜率、EV、P\*、仓位、三档价格 | **确定性 Python** | 算出来并**锁定**；LLM 写不进去 |

LLM 提方案，闸门做裁决。agent 要改一个已经锁定的数字，必须附 `provenance`，而且这次
override 会**印在结论里**，不是悄悄替换掉计算值。缺输入 → **裁决被阻断**，绝不给默认值。

这也是它以 *skill* 而不是 library 形式发布的原因：`SKILL.md` 是 agent 载入的操作手册
（什么时候调用、输入契约是什么、不许做什么），Python 是执行体，闸门是两者之间的边界。

## 你可以直接这样问它

装成 skill 之后，下面这些都是可以直接说出口的话——agent 读 `SKILL.md`、跑管线、回结论：

> **「512800 现在能不能买？」**
> → PB 分位、象限、胜率、仓位、三档价格，以及每一条触发过的阻断理由。

> **「把这六只 ETF 扫一遍——银行、券商、半导体——只报值得看的。」**
> → 批量模式；一个进程摊薄固定成本，单只失败不会拖垮整批。

> **「上次你说证券是买点，现在为什么变中性了？」**
> → 上一份结论带着参数指纹，所以这个变化能归因到输入或框架修订——而不是模型的情绪。

## 快速上手

### A. 30 秒，不要 API key、不联网、不需要数据目录

只依赖 `requests`。

```bash
git clone https://github.com/xyd0803/Ashare-sector-rotation.git
cd Ashare-sector-rotation
pip install -r requirements.txt
python discipline.py --demo
```

### B. 作为 skill 装进 agent

把仓库放进 agent 的 skills 目录，让它读 `SKILL.md`：

```bash
# Claude Code 或兼容的 agent 框架
git clone https://github.com/xyd0803/Ashare-sector-rotation.git \
  ~/.claude/skills/ashare-sector-rotation
```

然后用自然语言提问即可。agent 读技能契约，自己决定调哪个入口，并受与人类操作者相同的
闸门约束。

### 自己验算

demo 里每个数字都能手算，而 `--selfcheck` 断言的是**中间步骤**，不是最终答案：

```bash
python discipline.py --selfcheck
```

```
[PASS] status=OK
[PASS] 胜率=90（80+5+5+5 封顶90）
[PASS] 象限=黄金买入区
[PASS] 仓位=25.2%（36%×0.7 极端赔率比偏保守）
[PASS] 尾部标红已触发
[PASS] §十三自检全通过
```

量升价升 80 分，前瞻 +5，PB 便宜 +5，催化 +5，封顶 90。仓位 30% × 1.2（前瞻）= 36%，
再因极端赔率比 × 0.7 = 25.2%。如果你不认同这套框架，你可以指着具体某一行说不同意——
这正是设计目的。

## 一份结论是怎么产出的

```
  输入（供需判断 + 估值分位 + 现金流代理）
     │
     ├─ gate_industry_cycle ── 行业周期量价口径（不是 ETF 自己的价格/成交量）
     ├─ gate_dual_source ───── 两个独立 PB 源必须在容差内一致
     ├─ data_health ────────── 四态：OK / DEGRADED / MISSING / INVALID
     │
     ├─ quant_winrate ──────── 已校准的六档表，或通过验证后的量化路径
     ├─ valuation_anchor ───── 按板块类型选 PB / PE / 混合主锚
     ├─ sector_pstar ───────── P* = 由 EV 块反推的主锚中位
     ├─ EV 块 ──────────────── 悲观 / 中性 / 乐观 / 极端 四档价
     │
     └─ gate_final ─────────── 极端赔率比、仓位上限、建仓方式
                                → 结论 + 阻断 + 告警 + 自检
```

闸门无法评估它的输入时返回 `MISSING`，而 `MISSING` **阻断**结论。任何东西都不会掉进默认值。

量价口径也被硬校验：「量」指行业出货量/订单量/产能利用率，「价」指产品价格/ASP——
**绝不允许**是 ETF 自己的换手率，也绝不是指数点位。agent 若想从 ETF 的 K 线讲逻辑，
会在输入契约处被拒，早于任何数字被算出来。

## 这个仓库不寻常的地方

### 1. 每条主张都必须能在「故意弄错」时活下来

`PITFALLS_REGISTRY.json` 记录了这套框架**真实踩过**的 22 个失效模式，每一条都指向一个
**真实存在、且把守卫拿掉就会变红**的测试。一条登记了却没有测试执行的坑，只是注释，而注释会腐烂。

它也记录被**证伪**的思路——那些看起来合理、最后被证据杀掉的路。多数项目只公布成功的那半，
而「不成立的那半」才是更有用的那半。

```bash
python check_pitfall_closure.py
```

### 2. 测试的目的是打坏闸门

`_test_*.py` 是红队套件，不是单元测试。它们注入每个闸门存在的理由——两个价格源差 1%、
估值序列在窗口中途偷偷换了口径、连接器返回空载荷、一个新鲜度闸把三十条无关告警倒进
单标的检查——然后断言闸门**会响**，且**响应是成比例的**。另有一批用例断言闸门在该安静时
**保持安静**：一个对什么都报警的闸门，和一个从不报警的闸门一样没用。

```bash
python -m pytest -q      # 12 项：8 个红队套件 + 4 项离线冒烟
```

### 3. 参数冻结并带指纹

`params.json` 带版本、冻结时间戳和哈希。每份结论都引用指纹（`params=1.11.0#d390ff51`），
所以不同调参下产出的结果**可辨识**，而不是悄悄变得不可比。

### 4. 缺数据是一等状态，不是一个布尔值

`DEGRADED` 会带上**实际损失了多少信心（百分点）**，并且印在结论上。目的是让人不用读代码
就能分清一个强结论和一个弱结论。

### 5. agent 没法悄悄改数

已锁定的机械字段拒绝写入，除非 override 携带 provenance，而且这次 override 会被打印出来。
这就是「AI 写了一份分析」和「AI 写了一份分析，并且这里是它唯一一处与模型判断不一致的地方」
之间的差别。

## 诚实的局限

先说清楚，因为一个把局限藏起来的框架不值得读。

- **胜率层有一部分是启发式的。** 当校准模型对某个板块尚未通过验证时，引擎回退到六档查表，
  并在结论上打印 `胜率模式: 六档表(回退)（⚠️ 非量化路径·结论须带此水印）`。它告诉你这个
  数字是哪条路来的，而不是把两条路说成等价。
- **单市场。** 围绕 A 股板块结构、以 PB 为主锚、5 年分位窗口构建。换到别的市场，主锚是
  **错的**，不只是没校准。
- **分位需要历史。** 短于五年的窗口支撑不起分位结论，引擎拒绝假装可以，也不外推。
- **不下单、不对接券商、不构成建议。** 它只输出文本和 JSON。
- **仓库不含行情数据。** 这是刻意的，见下一节。

## 数据、凭证，以及为什么仓库里没有数据

衍生行情数据的再分发权只属于生产它的供应商，所以 `data/` 被 git 忽略，仓库里只有代码，
外加一条**明确标注**的小样本序列供离线 demo 使用。`docs/DATA_SOURCES.md` 记录了凭证模型
（只走环境变量，绝不写字面量）并列出开源替代——AKShare、Tushare、Baostock、Qlib、交易所
公开数据——给不想用商业接口的人。

两道检查强制执行这件事，且都跑在 CI 上，因为本地 hook 可以被绕过：

```bash
python scripts/check_no_secrets.py      # 凭证字面量、个人路径、禁入目录
python scripts/check_public_ready.py    # 全历史：提交身份、blob、体积、离线 demo
```

本仓库的提交身份使用 GitHub `noreply` 地址，因此提交历史不携带联系方式。

```

```
