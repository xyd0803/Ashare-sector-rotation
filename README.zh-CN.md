# Ashare-sector-rotation

**A 股板块轮动的「纪律层」引擎。** 它把一份供需判断加一个估值分位，变成一份可审计的结论：
胜率、象限、建议仓位、三档价格——以及它**拒绝更乐观**的全部理由。

它不是预测模型，是一层纪律。

## 它要解决什么

多数板块轮动脚本回答的是「该买什么」。这个问题很容易答得很差，因为答案把关键信息
全藏起来了：哪些数字是假设的、哪些是取到的、缺了什么、以及某个输入错一点结论会漂多远。

这个项目回答的是另一个问题：**只凭我确实知道的东西，什么是站得住脚的仓位——以及什么情况下我会错？**

由此产生三条贯穿全代码的原则：

| 原则 | 具体表现 |
|---|---|
| 不猜 | 缺输入 → 结论被阻断，而不是填一个默认值。 |
| 全程可追 | 每份结论都带参数指纹（`params=1.11.0#d390ff51`）。 |
| 降级要量化 | 数据降级时明确报出**损失了多少**置信度（百分点）。 |

## 快速开始

不需要 API Key、不需要联网、不需要数据目录。只依赖 `requests`。

```bash
git clone https://github.com/xyd0803/Ashare-sector-rotation.git
cd Ashare-sector-rotation
pip install -r requirements.txt
python discipline.py --demo
```

真实输出（未编辑）：

```text
【证券】as_of=2026-11-02  status=OK  params=1.11.0#d390ff51
  需求: 结构性增长  量价: 量升价升 (5星)  前瞻: ↑
  估值主锚: PB
  PB: 1.36  分位 27.5% [5y]  校验: 双源一致(差0.7%)+手算校验✓
  胜率: 90%  象限: 黄金买入区  建议仓位: 25.2%
  胜率模式: 六档表(回退)（⚠️ 非量化路径·结论须带此水印）
  [O10] 风险预算 conviction=0.227（=仓位×胜率/100，跨板块加总须≤组合上限 60%）
  [EV] 三档价(相对现价=100): 悲观79.41 / 中性110.29 / 乐观138.97 / 极端69.85
  [EV] EV中=+7.2%  EV乐=+33.01%  EV尾=+6.25%
  [尾部] ⚠️ 尾部风险高（极端下行 30.1%>30%）：抄底须分批+严控单笔下注
  [执行] 极端赔率比 0.34<1 → 显著偏保守，仓位 ×0.7
  硬信号触发: 无
  §十三自检: 全通过
```

请再读一遍这段输出，注意它**没有**做的事：它没让你买。它报的是——风险预算 0.227，
上限 0.60；极端情形要亏 30.1%；因为这一点仓位被砍了 30%。取舍摆在明面上，结论由你下。

### 自己验算

demo 里每个数字都可手算，`--selfcheck` 断言的是中间步骤而非最终答案：

```bash
python discipline.py --selfcheck
```

```text
[PASS] status=OK
[PASS] 胜率=90（80+5+5+5 封顶90）
[PASS] 象限=黄金买入区
[PASS] 仓位=25.2%（36%×0.7 极端赔率比偏保守）
[PASS] 尾部标红已触发
[PASS] §十三自检全通过
```

「量升价升」80 分，前瞻 +5，PB 便宜 +5，催化 +5，封顶 90。仓位 30% × 1.2（前瞻）= 36%，
再因尾部赔率 × 0.7 = 25.2%。**如果你不认同这个框架，可以直接指出具体哪一行不认同**——
这正是它的意义。

## 一份结论是怎么产生的

```text
  输入（供需判断 + 估值分位 + 现金流代理）
     │
     ├─ gate_industry_cycle ── 行业周期量价口径（而非公司口径）
     ├─ gate_dual_source ───── 两个独立 PB 源须在容差内一致
     ├─ data_health ────────── 四态：OK / DEGRADED / MISSING / INVALID
     │
     ├─ quant_winrate ──────── 校准六档表，或经验证的量化路径
     ├─ valuation_anchor ───── 按板块类型选 PB / PE / 混合锚
     ├─ sector_pstar ───────── P* = 由 EV 块反推的锚中点
     ├─ EV 块 ──────────────── 悲观 / 中性 / 乐观 / 极端 四档价
     │
     └─ gate_final ─────────── 终闸：尾部赔率、仓位上限、建仓方式
                                → 结论 + 阻断项 + 告警 + 自检
```

评估不了输入的闸门返回 `MISSING`，而 `MISSING` 会阻断结论——**不会**悄悄退化成默认值。

## 这个仓库特别在哪

### 1. 坑是登记表，不是散文

`PITFALLS_REGISTRY.json` 记录框架踩过的每一个失效模式，`check_pitfall_closure.py`
**校验每条记录指向的测试确实存在、且把守卫去掉后确实会失败**。
没有测试执行的坑只是一句注释，而注释会腐烂。

```bash
python check_pitfall_closure.py
```

### 2. 测试是用来打守卫的

`_test_*_20261025.py` 是红队套件而非单元测试。它们注入每个守卫本来要拦的那种坏数据——
两个价格源差 1%、估值序列在窗口内悄悄换了口径、连接器返回空载荷——然后断言守卫
**确实触发**，且反应**成比例**。见谁都报警的守卫和从不报警的守卫一样没用，
所以有多个用例断言「该安静时必须安静」。

```bash
python -m pytest -q      # 11 项：7 个红队套件 + 离线 demo 冒烟
```

### 3. 参数冻结并留指纹

`params.json` 带版本号、冻结时间与哈希。结论引用指纹，于是「不同调参下的结果」
是可识别的，而不是悄悄不可比。

### 4. 缺数据是一等状态

四种数据状态不是布尔值。`DEGRADED` 携带真实损失的置信度（百分点），并盖在结论上。
目标是：读者不看代码也能分辨「强结论」和「弱结论」。

## 诚实的局限

先说清楚，因为藏起局限的框架不值得读。

- **胜率层部分是启发式的。** 当校准模型对某板块尚未验证时，引擎回退到六档查表，并在结论上打印
  `胜率模式: 六档表(回退)（⚠️ 非量化路径·结论须带此水印）`。它告诉你这个数字是哪条路径产出的，
  而不是把两者当成等价。
- **这是单一市场的框架。** 围绕 A 股板块结构、以 PB 为主锚、5 年分位窗口构建。
  换到别的市场，锚就是错的，不只是「未校准」。
- **分位需要历史。** 不足五年的窗口支撑不了分位结论，引擎会拒绝而不是外推。
- **无执行、无券商接口、不构成建议。** 它只输出文本与 JSON，不下单。
- **仓库不含任何行情数据**（原因见下）。

## 数据、凭证，以及为什么仓库里没有数据

派生行情数据的再分发权只属于原始供应商，因此 `data/` 被 git 忽略，仓库只有代码。
`docs/DATA_SOURCES.md` 说明了凭证模型（**只允许环境变量，不允许字面量**），并列出
开放替代方案——AKShare、Tushare、Baostock、Qlib、交易所公开文件——给不想使用商业接口的人。

提交钩子强制这一点：

```bash
python scripts/check_no_secrets.py     # 凭证字面量 / 个人绝对路径 / 禁入目录
```

同一条检查也在 CI 里跑，因为钩子是本地的、可以被绕过。

## 目录结构

```text
discipline.py              结论引擎；--demo 完全离线
run_sector_pipeline.py     批量管线（M1-M4）
gate_*.py                  闸门：行业周期 / 双源价格 / 终闸
data_health.py             四态数据健康度
quant_winrate.py           胜率查表 / 量化路径
valuation_anchor.py        按板块类型选锚
sector_pstar.py            P* 反推
params.json                冻结参数 + 指纹
PITFALLS_REGISTRY.json     坑 → 守卫测试 登记表
check_pitfall_closure.py   校验每个坑都有测试在执行
_test_*_20261025.py        红队套件（独立可跑，也能被 pytest 收集）
tests/                     pytest 包装 + 冒烟检查
scripts/                   数据准备、发布守卫、私有备份
docs/                      数据源与凭证模型
```
